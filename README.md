## 🧩 Что это такое

**IPA Patcher Lite** — портативный консольный инструмент для анализа, модификации и инъекции твиков в `.ipa` и `.tipa` (TrollStore) пакеты. Он умеет менять идентификаторы и метаданные приложения, настраивать entitlements, заменять иконку (с маскировкой `Assets.car` вместо его удаления), настраивать файловый шеринг, внедрять твики (`.dylib`, MobileSubstrate-пакеты, `.deb`, `.zst`, фреймворки), применять расширенные патчи (понижение версии iOS, снятие ограничений по устройствам, удаление плагинов), редактировать бинарники во встроенном Hex-патчере, просматривать и править файлы внутри `.app` через интерактивный файловый менеджер, удалять 32-битные архитектуры, восстанавливать файлы из резервных копий и готовить пакет к установке через **SideStore**, **AltStore** или **TrollStore** — без джейлбрейка, компилятора и сторонних библиотек.

Проект построен по концепции **Zero Dependencies**: `pip install` не требуется. Все низкоуровневые операции — разбор Mach-O и FAT/FAT64, инъекция `LC_LOAD_DYLIB`, побайтовая замена строк в памяти, декодирование архивов Zstandard и `ar`, маскирование B-дерева каталога ассетов `Assets.car` — реализованы на чистом Python и системных API iOS.

Скрипт оптимизирован для запуска на iPhone и iPad (**Pythonista 3**, **a-Shell mini**), а также работает нативно на macOS, Linux и Windows. Окружение определяется через `try/except import` и `sys.platform`, и под него адаптируются распаковка архивов, файловые диалоги и доступные системные функции (например, Share Sheet работает только в Pythonista на iOS). Все операции с файловой системой и архивами защищены от directory traversal и имеют ограничения на размер и структуру данных, чтобы не падать и не портить бинарники на повреждённых или враждебных входных файлах.

## 🏪 Поддержка TrollStore (.tipa)

Скрипт полностью поддерживает `.tipa` для TrollStore — специального формата, который требует особой подготовки пакета.

**Автоматические настройки для `.tipa`:**

- **Entitlements для TrollStore** — в `entitlements.plist` автоматически добавляются флаги:
  - `com.apple.developer.kernel.extended-virtual-addressing: true` — снятие лимитов ОЗУ
  - `com.apple.security.cs.allow-jit: true`
  - `com.apple.security.cs.allow-unsigned-executable-memory: true`
  - `com.apple.security.cs.disable-library-validation: true`
  - `get-task-allow: true`
- **Настройка Info.plist для совместимости:**
  - `UIApplicationSupportsMultipleScenes: false` — отключает поддержку нескольких сцен
  - `UISupportsDocumentBrowser: true` — включает браузер документов
  - `UIFileSharingEnabled: true` — включает файловый шеринг
  - `LSSupportsOpeningDocumentsInPlace: true` — поддержка открытия документов на месте
- **Упаковка без сжатия (`ZIP_STORED`)** — TrollStore требует несжатые `.tipa` для быстрой установки. Скрипт сам определяет формат и применяет нужный метод упаковки.
- **Автоопределение формата** — по расширению (`.tipa` / `.ipa`) на всех этапах: распаковка, редактирование, упаковка и установка.
- **Установка через TrollStore** — после сборки `.tipa` скрипт предлагает открыть Share Sheet; в Pythonista на iOS появится системное меню «Открыть в», где можно выбрать TrollStore.

**Особенности:**

- Весь функционал патчинга (имя, версия, Bundle ID, иконка, твики и т.д.) работает одинаково для `.ipa` и `.tipa`.
- Отличаются только метод упаковки (`ZIP_STORED` для `.tipa`, настраиваемое сжатие `ZIP_DEFLATED` для `.ipa`) и автоматические настройки entitlements.
- Итоговый файл получает расширение `.tipa` и сохраняется в `Patched_ipa`.

## 📁 Файловый шеринг: 3 режима

Пункт `5` открывает выбор из трёх стратегий:

|№|Режим                        |Что включается                                                                                        |
|-|-----------------------------|------------------------------------------------------------------------------------------------------|
|1|**Старый**                   |Только `UIFileSharingEnabled` — классический доступ к папке `Documents` приложения через iTunes/Finder|
|2|**Современный (iOS 14+)**    |Только `LSSupportsOpeningDocumentsInPlace` — открытие документов на месте через приложение «Файлы»    |
|3|**Гибридный (рекомендуется)**|Оба ключа одновременно — максимальная совместимость со старыми и новыми версиями iOS                  |

Независимо от режима всегда дополнительно включается `UISupportsDocumentBrowser`, который делает папку приложения видимой в системном браузере файлов — без этого ключа приложение может не отображаться в списке «На iPhone» даже с включённым шерингом.

При выборе конкретного режима «лишний» ключ из другого режима удаляется из `Info.plist`, если он там был, — переключение между режимами при повторном патче происходит чисто, без накопления неиспользуемых ключей.

## 🖼️ Замена иконки: 5 методов

Пункт `6` открывает выбор из пяти стратегий (`icon_tools/icon_manager.py`, `icon_generator.py`, `boms_editor.py`). Поддерживаются только PNG-файлы в качестве источника.

|№|Метод                           |Что происходит                                                                                                                                                                                                                                                                                                               |
|-|--------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|1|**Гибридный (рекомендуется)**   |Последовательно: обработка всех бандлов (главный + `.appex` / `Watch` / виджеты) → стандартная файловая замена существующих иконок → маскировка токенов в `Assets.car` → legacy loose-метод с очисткой современных ключей `CFBundleIcons`. `Assets.car` остаётся на месте — приложение не падает из-за отсутствующих ресурсов|
|2|**Только маскировка Assets.car**|Патчит только бинарный BOM-индекс (`patch_boms_icon`), без замены файлов иконок — самый безопасный, но менее надёжный способ заставить iOS не использовать кэш                                                                                                                                                               |
|3|**Только loose-иконки**         |Генерирует полный набор PNG нужных размеров (`generate_loose_icons`) и переписывает `CFBundleIcons*` / `CFBundleIconFiles` в `Info.plist`, чтобы iOS брала иконки из файлов, а не из `Assets.car`                                                                                                                            |
|4|**Только стандартная замена**   |Ищет существующие файлы иконок по именам из `Info.plist` и подменяет их напрямую (`replace_icon_standard`)                                                                                                                                                                                                                   |
|5|**Удалить Assets.car**          |⚠️ Требует отдельного подтверждения — на iOS/iPadOS 15+ приложение может крашиться при запуске без `Assets.car`                                                                                                                                                                                                               |

**Как работает анализ (`icon_tools/icon_analyzer.py`):**

- Извлекает имена иконок из `CFBundleIcons`, `CFBundleIcons~ipad`, легаси `CFBundleIconFiles` и `CFBundleIconName`.
- Строит полный список возможных вариантов имён (`@2x` / `@3x`, `~iphone` / `~ipad`, стандартные `AppIcon*` / `Icon*`, `iTunesArtwork`) и сканирует директорию `.app` на совпадения regex-паттерном.
- При наличии **Pillow** — ресайзит источник под нужный размер (LANCZOS/ANTIALIAS в зависимости от версии) и квантует мелкие иконки (≤40×40) до 128 цветов; без Pillow — прямое копирование оригинала без ресайза и без ошибки.
- После успешной замены **автоматически увеличивает `CFBundleVersion`** на 1 (`increment_bundle_version`), чтобы SpringBoard сбросил кэш иконок.

**Маскировка Assets.car (`icon_tools/boms_editor.py`):**

Файл `Assets.car` — это `BOMStore`-контейнер (Bill of Materials), внутри которого находятся индексные ключи вида `CFBundleIconFiles`, `AppIcon-` и т.д. Модуль ищет эти ключи побайтово и заменяет их на строки **той же длины** (`XFBundleIconFiles`, `XppIcon-` и т.п.), не трогая остальную структуру файла. Это «отключает» привязку системы к закэшированным иконкам внутри `Assets.car`, не удаляя сам файл и не ломая остальные ресурсы (шрифты, изображения интерфейса и т.д.).

## 💉 Инъекция твиков подробно

### Поддерживаемые форматы

|Формат                                       |Обработка                                                                                                                                                                                                                                             |
|---------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|`.dylib`                                     |Проверяются заголовки Mach-O (`verify_dylib_headers`): magic-число, разрядность, наличие ARM64/ARM64e-среза; 32-битные файлы отклоняются; при неудачной проверке запрашивается подтверждение «на свой риск». Инъекция выполняется сразу, без архивации|
|`.zip`                                       |Распаковывается стандартным `zipfile` с фильтрацией путей на traversal; если внутри одна папка — она становится корнем поиска                                                                                                                         |
|`.deb`                                       |Встроенный парсер `ar` (на iOS — через системную `libarchive.2.dylib`, на macOS/Linux — через утилиту `ar`, иначе — чистый Python). Затем рекурсивно ищется и распаковывается вложенный `data.tar.{gz,xz,lzma,zst}`                                   |
|`.tar`, `.lzma`, `.xz`, `.gz`, `.tgz`, `.zst`|На iOS — через `libarchive.2.dylib`; на остальных платформах — через `tarfile` с проверкой путей и корректным разрешением символических ссылок; `.zst` — через `zstd_lite.py`                                                                         |

### Что и как ищется внутри архива

1. **`Library/MobileSubstrate/DynamicLibraries/`** — основной путь поиска `.dylib`; корректно разрешает симлинки (`os.readlink`), если найдена ссылка вместо файла.
1. Если такой папки нет — поиск `.dylib` идёт рекурсивно по всему архиву.
1. **`Library/Frameworks/*.framework`** копируются целиком (с fallback-поиском по всему дереву, если структуры `Library/Frameworks` нет).
1. Для `.deb` дополнительно разбирается `DEBIAN/control` — из поля `Depends:` резолвятся зависимости (сначала как `.dylib`, потом как `.framework`) и подтягиваются, если найдены в архиве.
1. Любые `*.bundle`-директории копируются в `Frameworks/` как есть (ресурсы твика).
1. Папки `Applications/` и `DEBIAN/` удаляются как непригодные для пользовательского приложения.

### Пайплайн инъекции

1. Проверка, что главный исполняемый файл (`CFBundleExecutable`) — валидный Mach-O с поддерживаемой архитектурой (ARM64/ARM64e; чистый ARMv7/v7s отклоняется).
1. Если бинарник FAT — он утоньшается до arm64-среза (`thin_binary_to_arm64`).
1. Создаётся `Frameworks/`, туда копируются найденные `.dylib` / `.framework` / `.bundle`; для каждого файла проверяются подозрительные системные вызовы и патчатся пути к CydiaSubstrate на `sb.dylib`.
1. Оценивается количество модулей (`count_modules_in_tweak`) и заранее проверяется, хватит ли места в заголовке Mach-O под нужные load-команды.
1. В главный бинарник добавляются `LC_RPATH` для `@executable_path/` и `@executable_path/Frameworks`.
1. Если субстрат включён — `libsubstrate.dylib` / `libellekit.dylib` (или выбранный вручную файл) копируется как `sb.dylib` в корень `.app`, в бинарник добавляется `LC_LOAD_DYLIB`.
1. Во всех скопированных Mach-O файлах побайтово патчатся старые пути (`/Library/MobileSubstrate/DynamicLibraries/`, пути к фреймворкам) на новые (`@executable_path/...`, `@rpath/...` или `@loader_path/...`, в зависимости от режима) с сохранением 8-байтного выравнивания структур.
1. Для каждого `.dylib` и `.framework` в главный бинарник добавляется собственный `LC_LOAD_DYLIB`; те же действия выполняются для всех `PlugIns/*.appex`.
1. Если ни одна инъекция не удалась (не хватило места в заголовке) — операция считается неуспешной, и пользователю сообщается об этом.

## 🗜️ Zstandard и распаковка архивов

Скрипт готов к современным Rootless-пакетам:

- **Распаковка `.deb`** — встроенный парсер формата `ar` вскрывает пакет без сторонних утилит.
- **Поддержка `.zst`** — `core/zstd_lite.py` распаковывает `data.tar.zst` и `control.tar.zst` на чистом Python, без внешних процессов. Это решает проблему блокировки `subprocess` в iOS-песочницах.
- **Фоллбэк на системный libarchive** — для архивов LZMA/XZ используется нативная `/usr/lib/libarchive.2.dylib` через `ctypes` (обходит отсутствие модуля `_lzma` в Pythonista).
- **Защита при распаковке** — все пути проверяются на выход за пределы целевой директории (через `realpath`), символические ссылки разрешаются безопасно.

## 🧩 Менеджер субстратов и ElleKit

В версии 1.1.5 полностью удалены устаревшие и несовместимые с песочницей субстраты (libhooker, roothide, TweakInject, pspawn), создававшие мусорные зависимости в бинарниках. Архитектура сфокусирована на **ElleKit** и автономном **Jailed Substrate**.

**Пункт меню 11 (Управление субстратами):**

- Автоматически сканирует папку `assets/` и выводит список всех сохранённых библиотек с выбором по номеру.
- **Опция `i` (Импорт):** принимает `ellekit.deb` или `libellekit.dylib`, фильтрует системный мусор джейлбрейка, сохраняет ядро `libellekit.dylib` в `assets/` и сразу активирует его.
- **Опция `n` (Без субстрата):** отключает субстрат — необходимо для современных автономных модов вроде YTLite или BHTwitter.

**Встроенные предохранители:**

- Если в приложении уже есть `sb.dylib`, скрипт предупреждает об этом перед заменой и запрашивает подтверждение.
- При переключении в режим «Без субстрата» скрипт предлагает удалить старый `sb.dylib` из приложения, гарантируя чистоту бинарника.

## 🔐 Entitlements

Пункт меню `13` генерирует `entitlements.plist` в директории `.app`:

- **Team ID** автоматически извлекается из `embedded.mobileprovision` (поле `ApplicationIdentifierPrefix`). Если провижн отсутствует или не читается — используется заглушка `TEAMID12345` (будет заменена при переподписи).
- Всегда прописываются `application-identifier` и `com.apple.developer.team-identifier`.
- Удаляются потенциально проблемные ключи (`application-groups`, `associated-domains`, `ubiquity-kvstore-identifier`, `icloud-container-identifiers`), если они пришли из исходного пакета.
- **Для любого аккаунта** можно включить:
  - `get-task-allow` — нужно для JIT / отладки твиков / эмуляторов.
  - Extended Virtual Memory (`com.apple.developer.kernel.extended-virtual-addressing`) — снятие лимитов ОЗУ для тяжёлых модов и игр.
- **Только для платного Apple ID ($99)** дополнительно доступны:
  - Push-уведомления (`aps-environment`).
  - Associated Domains (универсальные ссылки).
  - iCloud (`icloud-container-identifiers`, `icloud-services`).
- **Для `.tipa`** автоматически добавляются TrollStore-флаги:
  - `com.apple.developer.kernel.extended-virtual-addressing: true`
  - `com.apple.security.cs.allow-jit: true`
  - `com.apple.security.cs.allow-unsigned-executable-memory: true`
  - `com.apple.security.cs.disable-library-validation: true`
  - `get-task-allow: true`

## 🧬 Глубокая замена Bundle ID / версии

Помимо правки `Info.plist`, при смене Bundle ID или версии (пункты `2` и `4`, а также при правке через JSON-редактор) можно выбрать **глубокую замену**. Она реализована единой функцией `deep_patch_string_in_bundle`:

- Скрипт проходит по всем файлам `.app`, пропуская медиа, шрифты, скомпилированные сториборды, `.car`, а также `Info.plist`, `entitlements.plist` и `embedded.mobileprovision`.
- Mach-O бинарники патчатся через `patch_strings.py` (безопасная побайтовая замена с `\x00`-паддингом через `mmap`, без сдвига файла); в лог выводится **точное число замен** в каждом файле.
- Обычные файлы (json, конфиги, файлы движков вроде `global-metadata.dat` в Unity) патчатся прямой заменой байтовой строки; лимит размера файла — **200 МБ**.
- **Ограничение:** новое значение не должно быть длиннее старого в байтах UTF-8, иначе глубокая замена для конкретного файла пропускается (замена в `Info.plist` всё равно применяется).
- Bundle ID дополнительно каскадно обновляется в `Info.plist` всех `PlugIns/*.appex` и `Watch/*.app`.

## 🔧 Hex-патчер

Пункт меню `15` открывает встроенный интерактивный Hex-редактор (`hex_patcher/`). Он позволяет выполнять низкоуровневый поиск и замену байтов и строк прямо внутри файлов уже распакованного `.app` — без повторной сборки IPA и открытия во внешнем Hex-редакторе.

После выбора `.app` доступны все его файлы (основной бинарник, `Assets.car` и любые другие). Возможности:

- **Мобильная сетка 16 байт** — адреса и hex-колонки оптимизированы под ширину экрана iPhone в a-Shell mini и не переносятся на новую строку.
- **Нативная подсветка в Pythonista 3** — вместо терминальных ANSI-кодов используется `console.set_color()`; совпадения подсвечиваются зелёным и в HEX, и в строке символов.
- **Просмотр дампа файла** — постраничная навигация с настраиваемым интервалом и количеством строк, переход по смещению (`o`) и по строкам (`g`); крупные файлы (>10 МБ) обрезаются до первых 10 МБ для быстрой навигации.
- **Поиск** HEX-последовательностей, точных строк и строк без учёта регистра, поддержка масок; найденные смещения сохраняются и могут быть использованы для замены.
- **Отображение полного контекста** — парсер определяет границы всей C-строки вокруг найденного фрагмента и выводит `[Контекст текста]: "Полная фраза"`.
- **Умная замена строки целиком** — если найден короткий фрагмент длинной фразы, патчер предлагает отредактировать всю строку с автоматическим расчётом доступного пространства и добивкой нулями `\x00`.
- **Поиск и замена** HEX или текста — пакетная замена всех совпадений или только выбранных номеров.
- **Редактирование по смещению** — замена байтов с конкретного адреса (hex или decimal) с предпросмотром текущих байтов и их ASCII-представления.
- **Список найденных смещений** — все совпадения нумеруются, можно быстро переключаться между ними.

**Структура модуля `hex_patcher/`:**

- `core/` — движок патчинга с масками, журнал транзакций (undo), исключения, типы данных.
- `analyzers/` — анализ структуры Mach-O и поисковые алгоритмы.
- `managers/` — управление бэкапами и историей изменений (`undo_log.json`).
- `utils/` — вспомогательные функции для дампа и конвертации hex/ASCII.
- `interactive.py` — интерактивный консольный интерфейс.
- `json_patcher.py` — загрузка и сохранение наборов патчей в JSON (повторное применение одинаковых правок к разным сборкам).

Все изменения применяются прямо к файлам во временной директории сборки. При использовании Hex-патчера устанавливается флаг `hex_patcher_used`, и итоговый IPA/TIPA автоматически получает суффикс `_patched`, даже если больше ничего не менялось. По завершении работы `undo_log.json` удаляется вместе с содержимым `Temp_ipa/`.

## 🩻 Прореживание бинарника

Пункт меню `16` удаляет 32-битные архитектуры (ARMv7/v7s) из FAT-бинарника (включая FAT64), оставляя только ARM64/ARM64e. Это освобождает место в заголовке Mach-O для инъекции твиков и уменьшает размер бинарника.

**Как работает:**

1. Проверяет, является ли бинарник FAT (универсальным); корректно читает FAT64 (`FAT_MAGIC_64`).
1. Определяет список архитектур (`cputype_12` = ARMv7, `arm64` = ARM64).
1. Если обнаружены 32-битные архитектуры — предлагает их удалить.
1. Создаёт бэкап оригинального бинарника (`.bak_thin`).
1. Выполняет прореживание через `thin_binary_to_arm64`.
1. Показывает освобождённый объём и новую архитектуру.

**Важно:** после прореживания приложение становится несовместимым с 32-битными устройствами (iPhone 5 и старше).

## 🛡️ Безопасность и отказоустойчивость

- **Path traversal / Zip Slip защита** — при распаковке `.ipa`, `.tipa`, `.zip`-твиков и любых архивов пути проверяются на выход за пределы целевой директории (через `realpath`).
- **Строгий парсинг Mach-O** — функции разбора load-команд ограничивают `ncmds` (не более 1000), `cmdsize` (не более 4096 байт) и число архитектур в FAT-бинарнике (1–20).
- **Контроль заголовков Mach-O** — расчёт свободного места между заголовками и первой секцией (`min_section_offset`) предотвращает повреждение кода при добавлении load-команд.
- **Поддержка FAT64** — корректное чтение и прореживание 64-битных универсальных бинарников.
- **Соблюдение выравнивания** — сохранение 8-байтного выравнивания структур Mach-O при патчинге путей.
- **Сканирование dylib на подозрительные вызовы** — перед добавлением зависимости проверяется наличие `system`, `popen`, `exec*`, `fork`, `ptrace`, IOKit-функций.
- **Фильтрация ложных срабатываний** — эвристика `_is_ascii_context` предотвращает ложные тревоги на случайные байты в инструкциях ARM64.
- **Проверка заголовков dylib перед инъекцией** — отклоняет 32-битные dylib и файлы без валидного ARM64/ARM64e среза.
- **Безопасная запись plist** — `save_plist_safe` умеет восстанавливать повреждённые XML/bplist файлы.
- **Санитизация имён файлов** — предотвращается выход за пределы директории через `../` или абсолютные пути.
- **Строгая валидация y/n-ввода** — только явные `y`/`yes`/`д`/`да` или `n`/`no`/`н`/`нет`.
- **Ограничения размера при глубоком патче** — единый лимит 200 МБ на файл.
- **Бэкапы, undo и автооткат** — для Hex-патчера и файлового менеджера.
- **Предохранители субстрата** — подтверждение перед перезаписью существующего `sb.dylib`.
- **Автоочистка временных артефактов** — `Temp_ipa/` и `undo_log.json` удаляются в блоке `finally`, даже при ошибке или прерывании.
- **Умный поиск файлов** — приоритет у `~/Documents/tmp`, что исключает ошибки доступа к системной `/tmp`.

## 🔬 Работа с Mach-O

Весь разбор и модификация бинарников реализована вручную через `struct`, без сторонних библиотек:

- **`is_macho_binary`** — определяет тип файла по magic-числу (`MH_MAGIC_64`, `MH_CIGAM_64`, `MH_MAGIC_32`, `MH_CIGAM_32`, `FAT_MAGIC`, `FAT_CIGAM`, `FAT_MAGIC_64`).
- **`inject_lc_load_dylib`** — добавляет load-команду `LC_LOAD_DYLIB`; перед вставкой ищет свободное место и отказывается работать, если его недостаточно.
- **`inject_rpath`** / **`has_rpath`** — добавляет и проверяет наличие `LC_RPATH`.
- **`inject_code_signature`** — низкоуровневая запись `LC_CODE_SIGNATURE`.
- **`is_ipa_encrypted`** — читает `LC_ENCRYPTION_INFO` / `LC_ENCRYPTION_INFO_64` и поле `cryptid`.
- **`thin_binary_to_arm64`** — вырезает arm64/arm64e-срез из FAT/FAT64-бинарника.
- **`verify_binary_architecture`** — отклоняет 32-битные (ARMv7/v7s) бинарники и FAT-файлы без современного 64-битного среза.

## 🌐 Web Transfer — передача файлов по Wi-Fi

`web_transfer.py` — независимый вспомогательный модуль (`python3 web_transfer.py`) для загрузки `.ipa` / `.tipa` / `.zip` / `.deb` / `.dylib` на устройство без кабеля.

**Безопасность:**

- Доступ защищён 6-значным ПИН-кодом (генерируется случайно, сравнение через `secrets.compare_digest`).
- Rate-limit: не более 5 запросов в минуту с одного IP.
- Автобан IP на 10 минут после 5 неудачных попыток ввода ПИН; чёрный список сохраняется в `blacklist.json`.
- Ограничение одновременных соединений (`MAX_CONNECTIONS`).
- Проверка расширений (`.ipa`, `.tipa`, `.zip`, `.deb`, `.dylib`) и лимит размера файла (5 ГБ).
- Санитизация имён файлов и защита от directory traversal.
- HTTP-заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, CSP, `Referrer-Policy`.
- Отдельные логи: `web_transfer.log` и `audit.log` (с маскированием IP).

**Использование:** запусти модуль, выбери «Запустить защищённый сервер» в меню, открой `http://<IP>:8080` в браузере, введи ПИН и перетащи файл.

## ❓ FAQ

**Нужен ли джейлбрейк?**
Нет. Установка через AltStore, SideStore или TrollStore работает на стоковой iOS.

**Какие платформы поддерживаются?**
Pythonista 3 и a-Shell mini на iOS/iPadOS, а также нативный Python на macOS, Linux и Windows.

**Можно ли откатить изменения?**
Скрипт никогда не изменяет исходный файл — результат всегда сохраняется в новый файл с суффиксами (`_tweaked`, `_icon`, `_patched`). Точечные правки можно откатить через undo Hex-патчера, автооткат файлового менеджера и пункт меню `17`.

**Почему инъекция твика не удалась?**
Нехватка места в заголовке Mach-O, неподдерживаемая архитектура (32-бит) либо зашифрованный исходный файл (App Store бинарник без расшифровки). Попробуй пункт `16` (прореживание).

**Какой режим файлового шеринга выбрать?**
Гибридный (`3`) — совместим со старыми и новыми версиями iOS.

**Какой метод замены иконки выбрать?**
Гибридный (`1`) — безопасный и эффективный; не удаляет `Assets.car` и не вызывает крашей на iOS 15+.

**Обязателен ли Pillow?**
Нет. Без Pillow иконки копируются без ресайза, но функционально работают.

**Поддерживаются ли `.deb` и `.zst`?**
Да: рекурсивная распаковка `data.tar.*` (включая `.zst` через встроенный декодер) и резолвинг зависимостей из `DEBIAN/control`.

**Что если новый Bundle ID или версия длиннее старых?**
Глубокая замена для такого файла пропускается, но `Info.plist` обновляется.

**Обязателен ли субстрат?**
Нет. Он нужен только для твиков, которым требуется Substrate/ElleKit. Для автономных модов выбери «Без субстрата» (`n` в пункте 11). Свой субстрат можно импортировать опцией `i`.

**Чем `.tipa` отличается от `.ipa`?**
`.tipa` — формат TrollStore: упаковывается без сжатия (`ZIP_STORED`) и получает специальные entitlements-флаги. Скрипт определяет формат автоматически.

**Можно ли патчить `.tipa` так же, как `.ipa`?**
Да, весь функционал одинаков для обоих форматов; отличаются только упаковка и автоматические entitlements.
