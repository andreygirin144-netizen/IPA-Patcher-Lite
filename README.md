## 🧩 Что это такое

**IPA Patcher Lite** — консольный (и нативный для iOS) инструмент для модификации `.ipa`-пакетов: смены идентификаторов и метаданных приложения, настройки entitlements, гибридной замены иконки (с маскировкой `Assets.car` вместо его удаления), включения файлового шеринга, инъекции твиков (`.dylib`, MobileSubstrate-пакеты, `.deb`, фреймворки), расширенных патчей (понижение версии iOS, снятие ограничений по устройствам, удаление плагинов), встроенного Hex-редактора для точечного бинарного патчинга и подготовки пакета к установке через **SideStore** или **AltStore** — без джейлбрейка, компилятора и сторонних библиотек.

Парсер Mach-O, инъектор load-команд и распаковщик архивов написаны на чистом Python и работают даже внутри **Pythonista 3** на iPhone/iPad. Вне Pythonista (macOS/Linux) скрипт автоматически переключается в консольный режим через `try/except import`. Все операции с файловой системой и архивами защищены от directory traversal и содержат ограничения на размер/структуру данных, чтобы не падать и не портить бинарники на повреждённых или враждебных входных файлах.

## ✨ Возможности

|Категория                                   |Описание                                                                                                                                                                                                                            |
|--------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|📦 **Распаковка / упаковка IPA**             |Извлекает и собирает `.ipa` (ZIP) с сохранением Unix-прав доступа, симлинков и адаптивным прогресс-баром; защита от Zip Slip / path traversal при распаковке и упаковке                                                             |
|✏️ **Редактирование Info.plist**             |Имя (`CFBundleDisplayName` / `CFBundleName`), версия (`CFBundleShortVersionString`), номер сборки (`CFBundleVersion`); безопасное чтение/запись plist с fallback-восстановлением повреждённых файлов                                |
|🔑 **Смена Bundle ID**                       |Каскадно обновляет идентификатор в основном `Info.plist`, во всех `PlugIns/*.appex`, в `Watch/*.app` и любых вложенных `.appex` по дереву `.app`                                                                                    |
|🧬 **Глубокая замена ID и версии**           |Опциональный побайтовый патч Bundle ID и версии внутри всех Mach-O бинарников и текстовых файлов пакета (кроме `Info.plist`, `entitlements.plist`, `embedded.mobileprovision`)                                                      |
|🔐 **Настройка Entitlements**                |Генерация `entitlements.plist` с автоопределением Team ID из `embedded.mobileprovision`, поддержка бесплатных и платных Apple ID (JIT/get-task-allow, Extended VM, Push, Associated Domains, iCloud)                                |
|🖼️ **Гибридная замена иконки**               |5 методов на выбор: гибридный (маскировка `Assets.car` + loose-иконки), только маскировка BOM-индекса, только loose-иконки, стандартная файловая замена, полное удаление `Assets.car`. `Assets.car` по умолчанию остаётся нетронутым|
|🎨 **Оптимизация иконок через Pillow**       |Автоматический ресайз под нужный размер (`@2x`/`@3x`/`~ipad`), квантование мелких значков, при отсутствии Pillow — безопасный fallback на прямое копирование                                                                        |
|🔢 **Автоинкремент CFBundleVersion**         |При замене иконки автоматически увеличивает номер сборки, чтобы iOS сбросила кэш иконок в SpringBoard                                                                                                                               |
|💉 **Инъекция твиков**                       |`.dylib`, `.zip`, `.deb` (с рекурсивной распаковкой `data.tar.*`), `.tar`, `.lzma`, `.xz`, `.gz`, `.tgz` — фреймворки, бандлы и динамические библиотеки автоматически находятся и копируются в `Frameworks/`                        |
|🧬 **Substrate-инъекция**                    |Три режима: автоматическая (встроенный `libsubstrate.dylib` рядом со скриптом), ручная (свой `.dylib`) или полное отключение                                                                                                        |
|🛡️ **Проверка dylib перед инъекцией**        |Валидация заголовков Mach-O (`verify_dylib_headers`), отклонение 32-битных файлов, сканирование на подозрительные системные вызовы (`system`, `popen`, `exec*`, IOKit-функции) перед копированием в бандл                           |
|🛣️ **@rpath / @executable_path**             |Переключаемый режим путей загрузки динамических библиотек                                                                                                                                                                           |
|📁 **Поддержка файлов**                      |Включает `UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace` и создаёт папку `Documents` с правами `0o755`                                                                                                                  |
|🔍 **Проверка шифрования**                   |Определяет `LC_ENCRYPTION_INFO` / `LC_ENCRYPTION_INFO_64` (`cryptid`) перед инъекцией, чтобы не сломать зашифрованный бинарник                                                                                                      |
|🩻 **Проверка архитектуры и thinning**       |Валидирует, что бинарник ARM64/ARM64e (отклоняет чистый ARMv7/v7s), и автоматически “утоньшает” FAT-бинарник до arm64-среза перед инъекцией                                                                                         |
|🧵 **Патч строк в бинарниках**               |Побайтовая замена путей загрузки во всех Mach-O файлах внутри `Frameworks/` с сохранением длины и `\x00`-паддинга (через `mmap`)                                                                                                    |
|🛠️ **Расширенные патчи**                     |Понижение `MinimumOSVersion`, удаление `UISupportedDevices`, удаление `PlugIns` (расширений), удаление Apple Watch компонентов, удаление `CFBundleURLTypes`, фикс белой иконки                                                      |
|📝 **Расширенное редактирование JSON**       |Полный `Info.plist` экспортируется во временный JSON-файл, который можно отредактировать в любом текстовом редакторе и применить целиком                                                                                            |
|🔧 **Hex патчер**                            |Встроенный интерактивный Hex-редактор (пункт 15) для поиска и замены HEX/строк в любом файле `.app`; поддержка масок и просмотра контекста; изменения сохраняются в файлах и попадают в финальный IPA                               |
|🧹 **Удаление подписи**                      |Чистит `_CodeSignature/`, `SC_Info/`, `embedded.mobileprovision`, `CodeResources` по всему дереву `.app`                                                                                                                            |
|🗂️ **Чистка мусорных папок**                 |Удаляет `Library`, `Applications`, `DEBIAN`, оставшиеся после установки твиков                                                                                                                                                      |
|📲 **Прямая отправка в SideStore / AltStore**|Открывает системный iOS Share Sheet                                                                                                                                                                                                 |
|🌐 **Web Transfer**                          |Отдельный модуль — локальный HTTP-сервер с ПИН-кодом, rate-limit’ом и авто-баном для передачи `.ipa`/`.zip`/`.deb`/`.dylib` на устройство по Wi-Fi без кабеля и iTunes                                                              |
|📱 **Нативный UI на iOS**                    |Все диалоги выбора файлов реализованы через `dialogs.pick_document` (Pythonista), а вне Pythonista — через обычный `input()` в терминале                                                                                            |

## 🗂 Структура проекта

```
├── entitlements.py         # Генерация entitlements.plist, автоопределение Team ID из mobileprovision
├── advanced_patches.py     # Понижение iOS, удаление плагинов/Watch/URL-схем, фикс белой иконки

├── boms_editor.py          # Маскировка токенов CFBundleIconFiles/AppIcon в бинарном индексе Assets.car (BOMStore)
├── ipa_utils.py            # Распаковка/упаковка ZIP с защитой от traversal, файловые диалоги, ввод данных
├── tweak_injector.py       # Безопасная распаковка .deb/.zip/.tar.*, проверка dylib, поиск и инъекция твиков
├── macho.py                # Низкоуровневый парсер Mach-O: LC_LOAD_DYLIB, LC_RPATH, LC_CODE_SIGNATURE, детект шифрования, thinning
├── substrate.py            # Копирование libsubstrate.dylib, патч путей зависимостей, сканирование на опасные вызовы
├── patch_strings.py        # Побайтовая замена путей/строк в бинарниках без изменения длины файла (через mmap)
├── signature.py            # Удаление файлов/папок подписи, отправка готового IPA в Share Sheet
├── web_transfer.py         # Локальный HTTP-сервер с ПИН-кодом для загрузки файлов на устройство по Wi-Fi
├── constants.py            # Магические числа Mach-O, load-команды, списки файлов подписи, PatchConfig
├── utils.py                # Логирование, цветной вывод в консоль, ввод пользователя (input-обёртки), пути к Logs/Patched
├── libsubstrate.dylib      # Стандартный субстрат для твиков (кладётся рядом со скриптом, опционально)
hex_patcher/
├── __init__.py             # Точка импорта, экспорт публичных классов (PatchEngine, start_hex_patcher)
├── core/                   # Ядро патчера
│   ├── __init__.py         # Экспорт ядра
│   ├── engine.py           # Двигатель: поиск по маске, замена HEX/строк/смещений, откат (undo), драйвер JSON-патчей
│   ├── exceptions.py       # Кастомные исключения (PatchError, SearchError, MachOError и т.д.)
│   └── types.py            # Перечисления (PatchType, SearchMode) и типы данных (MatchResult, MachOInfo)
├── analyzers/              # Анализаторы данных
│   ├── __init__.py
│   ├── macho.py            # Анализ Mach-O/FAT: получение архитектур, преобразование VA → file offset
│   └── search.py           # Поиск с маской ('?', '*', 'F?'): реализация через mmap и оптимизация фиксированных последовательностей
├── managers/               # Менеджеры состояний
│   ├── __init__.py
│   ├── backup.py           # Создание бекапов изменяемых файлов в папку
│   └── undo.py             # Логирование и откат изменений через JSON-журнал (undo_log.json)
├── utils/                  # Утилиты
│   ├── __init__.py
│   └── hex_utils.py        # Парсинг масок, конвертация HEX ↔ bytes, форматирование дампа/контекста
├── cli/                    # Интерфейс командной строки / интерактив
│   ├── __init__.py
│   └── interactive.py      # CL-обёртка: меню, Hex-редактор, полноэкранный дамп, поиск/замена, навигация по смещениям
└── json_patcher.py         # Загрузка и валидация JSON-патчей, поддержка legacy-форматов, сохранение патчей на диск
```

## 🚀 Установка

### 📱 iPhone / iPad — Pythonista 3

1. Установи [Pythonista 3](https://apps.apple.com/app/pythonista-3/id1085978097) из App Store.
1. Скопируй все файлы проекта (включая папку `hex_patcher/`) в **Pythonista → Documents** (`libsubstrate.dylib` — только если планируешь инъекцию твиков в режиме “авто”).
1. Готово — остальное работает на стандартной библиотеке.

### 📱 iPhone / iPad – a-Shell mini

1. Установи a‑Shell mini из App Store.
Открой a‑Shell mini и перейди в папку Documents:
`cd ~/Documents`
1. Скопируй все файлы проекта в эту папку (например, через iCloud Drive, AirDrop или файловый менеджер).
1. Запусти скрипт:
`python3 main.py`

### 🖥️ macOS / Linux / Windows – Python

```bash
git clone https://github.com/andreygirin144-netizen/ipa-patcher.git
cd ipa-patcher
pip install Pillow   # опционально, для качественной генерации иконок
python3 main.py
```

> На macOS/Linux/Windows функция Share Sheet Not supported, только для Pythonista (iOS/iPadOS)

## 🕹 Использование

### Pythonista 3 (iOS/iPadOS)

1. Открой `main.py` в Pythonista и нажми **▶ Run**.
1. Выбери `.ipa` через системный файловый пикер.
1. Дождись распаковки — длительность прогресс-бара зависит от размера файла (адаптивная задержка от 0 до 10 мс на файл).
1. Пройдись по пунктам меню (имя, версия, иконка, твики, entitlements, расширенные патчи, Hex-патчер и т.д.).
1. Выбери **9 — Применить изменения и собрать IPA**, подтверди сводку изменений.
1. Готовый файл появится в `~/Documents/IPA_Patcher_Patched/`.
1. Ответь “да” на вопрос об установке через SideStore/AltStore — откроется системный Share Sheet, либо позже поделись файлом вручную.

### a-Shell mini (iOS/iPadOS)

1. Открой a‑Shell mini, перейди в папку с проектом и запусти:
`python3 main.py`
1. Введи полный путь к .ipa файлу вручную (или предварительно скопируй его в `~/Documents/ipa_patcher/tmp/`).
1. Пройди по пунктам меню, используя цифровые клавиши и ввод.
1. На a‑Shell mini нет диалоговых окон — все операции выполняются через консоль.
1. Готовый IPA сохранится в `~/Documents/IPA_Patcher_Patched/`.

### Python (macOS / Linux / Windows)

```bash
python3 main.py
# → введи путь к .ipa файлу
# → пройди интерактивное меню
# → результат сохранится в ~/Documents/IPA_Patcher_Patched/
```

Логи всех операций пишутся в `~/Documents/IPA_Patcher_Logs/patcher.log`.

## 📋 Меню редактирования

|№   |Пункт                            |Что делает                                                                                                                                           |
|----|---------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|
|`1` |Имя приложения                   |Меняет `CFBundleDisplayName` и `CFBundleName`                                                                                                        |
|`2` |Версия                           |Меняет `CFBundleShortVersionString`; предлагает выбрать между безопасной заменой (только `Info.plist`) и глубокой (во всех файлах пакета)            |
|`3` |Номер сборки                     |Меняет `CFBundleVersion`                                                                                                                             |
|`4` |Bundle ID                        |Меняет `CFBundleIdentifier`; аналогично версии — выбор между безопасным и глубоким режимом замены                                                    |
|`5` |Поддержка файлов                 |Включает `UIFileSharingEnabled` и `LSSupportsOpeningDocumentsInPlace`                                                                                |
|`6` |Замена иконки                    |Открывает подменю из 5 методов замены (см. ниже)                                                                                                     |
|`7` |Инъекция твиков                  |Проверяет шифрование, архитектуру и заголовки dylib → запрашивает файл (`.dylib`/`.zip`/`.deb`/`.tar.*`) → проверяет место в заголовке → инъектирует |
|`8` |Просмотр файлов `.app`           |Генерирует текстовый список всех файлов бандла и открывает его в редакторе (если доступен)                                                           |
|`9` |Применить изменения и собрать IPA|Показывает полную сводку изменений (старое → новое) и текущую версию сборки, запускает упаковку                                                      |
|`10`|Тип пути                         |Переключает `@executable_path` ↔ `@rpath` для инъектируемых библиотек                                                                                |
|`11`|Режим субстрата                  |Циклически переключает: **авто** → **свой файл** → **без субстрата**                                                                                 |
|`12`|Расширенное редактирование (JSON)|Выгружает весь `Info.plist` в JSON, позволяет отредактировать его целиком в текстовом редакторе и применить обратно                                  |
|`13`|Настроить права (Entitlements)   |Генерирует `entitlements.plist` с учётом типа Apple ID (бесплатный / платный)                                                                        |
|`14`|Расширенные патчи                |Понижение iOS, удаление ограничений по устройствам, удаление плагинов/Watch/URL-схем, фикс белой иконки                                              |
|`15`|Hex патчер                       |Открывает встроенный Hex-редактор для поиска и замены HEX/строк в любом файле внутри `.app`. Позволяет быстро патчить бинарники, не выходя из скрипта|
|`0` |Выход без сохранения             |Завершает работу без изменений                                                                                                                       |

Перед сборкой скрипт всегда показывает **полную сводку изменений** и запрашивает финальное подтверждение.

## 🖼️ Замена иконки: 5 методов

Пункт `6` открывает выбор из пяти стратегий (`main.py` → `icon_manager.py` / `icon_generator.py` / `boms_editor.py`):

|№  |Метод                           |Что происходит                                                                                                                                                                                                                                                                                                               |
|---|--------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|`1`|**Гибридный (рекомендуется)**   |Последовательно: обрабатывает все бандлы приложения (главный + `.appex`/`Watch`) → стандартная файловая замена существующих иконок → маскировка токенов в `Assets.car` → legacy loose-метод с очисткой современных ключей `CFBundleIcons`. `Assets.car` остаётся на месте — приложение не падает из-за отсутствующих ресурсов|
|`2`|**Только маскировка Assets.car**|Патчит только бинарный BOM-индекс (`patch_boms_icon`), без замены файлов иконок — самый безопасный, но менее надёжный способ заставить iOS не использовать кэш                                                                                                                                                               |
|`3`|**Только loose-иконки**         |Генерирует полный набор PNG нужных размеров (`generate_loose_icons`) и переписывает `CFBundleIcons*`/`CFBundleIconFiles` в `Info.plist`, чтобы iOS взяла иконки из файлов, а не из `Assets.car`                                                                                                                              |
|`4`|**Только стандартная замена**   |Ищет существующие файлы иконок по именам из `Info.plist` и подменяет их напрямую (`replace_icon_standard`)                                                                                                                                                                                                                   |
|`5`|**Удалить Assets.car**          |⚠️ Требует отдельного подтверждения — на iOS/iPadOS 15+ приложение может крашиться при запуске без `Assets.car`                                                                                                                                                                                                               |

**Как работает анализ (`icon_analyzer.py`):**

- Извлекает имена иконок из `CFBundleIcons`, `CFBundleIcons~ipad`, легаси `CFBundleIconFiles` и `CFBundleIconName`.
- Строит полный список возможных вариантов имён (`@2x`/`@3x`, `~iphone`/`~ipad`, стандартные `AppIcon*`/`Icon*`, `iTunesArtwork`) и сканирует директорию `.app` на совпадения regex-паттерном.
- При наличии **Pillow** — ресайзит источник под нужный размер (LANCZOS/ANTIALIAS в зависимости от версии Pillow) и квантует мелкие иконки (≤40×40) до 128 цветов для меньшего размера файла; без Pillow — прямое копирование оригинала как fallback.
- После успешной замены **автоматически увеличивает `CFBundleVersion`** на 1 (`increment_bundle_version`), чтобы SpringBoard сбросил кэш иконок.

**Маскировка Assets.car (`boms_editor.py`):**
Файл `Assets.car` — это `BOMStore`-контейнер (Bill of Materials), внутри которого есть индексные ключи вида `CFBundleIconFiles`, `AppIcon-` и т.д. Модуль ищет эти ключи побайтово и заменяет их на строки **той же длины** (`XFBundleIconFiles`, `XppIcon-` и т.п.), не трогая остальную структуру файла. Это “отключает” привязку системы к закэшированным иконкам внутри `Assets.car`, не удаляя сам файл и не ломая остальные ресурсы (шрифты, изображения интерфейса и т.д.), которые там тоже могут храниться.

## 💉 Инъекция твиков подробно

### Поддерживаемые форматы

|Формат                               |Обработка                                                                                                                                                                                                 |
|-------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|`.dylib`                             |Проверяются заголовки Mach-O (`verify_dylib_headers`): magic-число, разрядность, наличие ARM64/ARM64e среза — отклоняются 32-битные файлы; при неудачной проверке запрашивается подтверждение на свой риск|
|`.zip`                               |Распаковывается стандартным `zipfile` с фильтрацией путей на traversal; если внутри одна папка — она становится корнем поиска                                                                             |
|`.deb`                               |Распаковывается через системную `libarchive.2.dylib` (ctypes) с проверкой путей записи, затем рекурсивно ищется и распаковывается вложенный `data.tar.{gz,xz,lzma}`                                       |
|`.tar`, `.lzma`, `.xz`, `.gz`, `.tgz`|Распаковываются через ту же `libarchive.2.dylib`                                                                                                                                                          |

### Что и как ищется внутри архива

1. **`Library/MobileSubstrate/DynamicLibraries/`** — основной путь поиска `.dylib`; корректно разрешает симлинки (`os.readlink`), если найдена ссылка вместо файла.
1. Если такой папки нет — поиск `.dylib` идёт рекурсивно по всему архиву.
1. **`Library/Frameworks/*.framework`** копируются целиком (с fallback-поиском по всему дереву, если структуры `Library/Frameworks` нет).
1. Для `.deb` дополнительно разбирается `DEBIAN/control` — из поля `Depends:` резолвятся зависимости (сначала как `.dylib`, потом как `.framework`) и подтягиваются, если найдены в архиве.
1. Любые `*.bundle`-директории копируются в `Frameworks/` как есть (ресурсы твика).
1. Папки `Applications/` и `DEBIAN/` удаляются как непригодные для пользовательского приложения.

### Пайплайн инъекции

1. Проверка, что главный исполняемый файл (`CFBundleExecutable`) — валидный Mach-O с поддерживаемой архитектурой (ARM64/ARM64e; чистый ARMv7/v7s отклоняется).
1. Если бинарник FAT — он “утоньшается” до arm64-среза (`thin_binary_to_arm64`).
1. Создаётся `Frameworks/`, туда копируются найденные `.dylib`/`.framework`/`.bundle`; для каждого зависимого файла проверяются подозрительные системные вызовы и патчатся пути к CydiaSubstrate на `sb.dylib`.
1. Оценивается количество модулей (`count_modules_in_tweak`) и заранее проверяется, хватит ли места в заголовке Mach-O под нужные load-команды.
1. В главный бинарник добавляются `LC_RPATH` для `@executable_path/` и `@executable_path/Frameworks`.
1. Если субстрат включён — `libsubstrate.dylib` (или выбранный вручную файл) копируется как `sb.dylib` в корень `.app`, в бинарник добавляется `LC_LOAD_DYLIB`.
1. Во всех скопированных Mach-O файлах побайтово патчатся старые пути (`/Library/MobileSubstrate/DynamicLibraries/`, пути к фреймворкам) на новые (`@executable_path/...` или `@rpath/...`, в зависимости от выбранного режима).
1. Для каждого `.dylib` и `.framework` в главный бинарник добавляется собственный `LC_LOAD_DYLIB`.
1. Если ни одна инъекция не удалась (не хватило места в заголовке) — операция считается неуспешной и сообщается пользователю.

## 🧬 Глубокая замена Bundle ID / версии

Помимо правки `Info.plist`, при смене Bundle ID или версии (пункты `2` и `4`) можно выбрать **глубокую замену**:

- Скрипт проходит по всем файлам `.app`, пропуская медиа/шрифты/скомпилированные сториборды/`.car`, а также `Info.plist`, `entitlements.plist` и `embedded.mobileprovision`.
- Mach-O бинарники патчатся через `patch_strings.py` (безопасная побайтовая замена с `\x00`-паддингом через `mmap`, без сдвига файла).
- Обычные файлы (json, конфиги) патчатся прямой заменой байтовой строки.
- **Ограничение:** новое значение не должно быть длиннее старого в байтах UTF-8 — иначе глубокая замена для конкретного файла пропускается (замена только через `Info.plist` всё равно применяется).
- Bundle ID дополнительно каскадно обновляется в `Info.plist` всех `PlugIns/*.appex` и `Watch/*.app`.

## 🔧 Hex патчер

Пункт меню `15` открывает встроенный интерактивный Hex-редактор (`hex_patcher/`). Он позволяет выполнять низкоуровневый поиск и замену байтов/строк прямо внутри файлов уже распакованного `.app` — без необходимости пересобирать IPA и заново открывать его в стороннем Hex-редакторе.

После выбора `.app` скрипт предоставляет доступ ко всем файлам внутри него (основной бинарник, `Assets.car` и любые другие). Внутри Hex-редактора доступны следующие функции:

- **Просмотр дампа файла** с настраиваемым интервалом, количеством строк и разбивкой; крупные файлы (>10 МБ) автоматически обрезаются до первых 10 МБ для быстрой навигации.
- **Поиск** HEX-последовательностей, точных строк и строк без учёта регистра; найденные смещения сохраняются и могут быть использованы для замены.
- **Поиск и замена** HEX или текста — поддерживается пакетная замена всех совпадений или только выбранных пользователем номеров.
- **Редактирование по смещению** — замена байтов начиная с конкретного адреса (hex или decimal) с предварительным просмотром текущих байтов и их ASCII-представления.
- **Список найденных смещений** — все совпадения выводятся с номерами, что позволяет быстро переключаться между ними и применять замены.

Модуль организован как отдельный подпакет `hex_patcher/`:

- `core/` — движок патчинга, исключения, типы данных.
- `analyzers/` — анализ структуры Mach-O и поисковые алгоритмы.
- `managers/` — управление бэкапами файлов и историей изменений (undo).
- `utils/` — вспомогательные функции для дампа и конвертации hex/ASCII.
- `cli/` — интерактивный консольный интерфейс редактора.
- `json_patcher.py` — загрузка и сохранение наборов патчей в формате JSON (для повторного применения одинаковых правок к разным сборкам).

Все изменения, внесённые через Hex-редактор, применяются прямо в файлах внутри временной директории сборки. Если Hex-редактор завершён через пункт меню **8 — Сохранить изменения и выйти**, флаг модификации передаётся обратно в главное меню, и итоговый IPA автоматически получает суффикс `_patched`. Скрипт при этом полностью сохраняет структуру файлов, не требует пересборки между правками и не отменяет изменения при выходе.

## 🛡️ Безопасность и защита

В основной пайплайн встроен ряд защитных механизмов, снижающих риск повреждения бинарников и файловой системы на нестандартных или вредоносных входных данных:

- **Path traversal / Zip Slip защита** — при распаковке `.ipa` (`ipa_utils.py`), `.zip`-твиков и архивов через `libarchive` (`tweak_injector.py`) все пути внутри архива проверяются на выход за пределы целевой директории (`os.path.realpath(...).startswith(...)`) перед извлечением.
- **Строгий парсинг Mach-O** — все функции разбора load-команд (`macho.py`) ограничивают `ncmds` (не более 1000), размер отдельной команды (`cmdsize` не более 4096 байт) и число архитектур в FAT-бинарнике (1–20), а также постоянно сверяют смещения с фактическим размером файла перед чтением/записью — это предотвращает падения и переполнения на повреждённых бинарниках.
- **Сканирование dylib на подозрительные вызовы** (`substrate.py`) — перед добавлением зависимости твика в бандл проверяется наличие символов вроде `system`, `popen`, `exec*`, `fork`, `ptrace`, IOKit-функций (`IOServiceMatching`, `IOConnectCallMethod` и т.д.); при обнаружении выводится предупреждение, но решение остаётся за пользователем.
- **Проверка заголовков dylib перед инъекцией** (`verify_dylib_headers` в `tweak_injector.py`) — отдельно от общей проверки архитектуры, отклоняет 32-битные dylib и файлы без валидного ARM64/ARM64e среза.
- **Безопасная запись plist** (`plist_editor.py`) — `save_plist`/`save_plist_safe` пишут в бинарном формате с автоматическим fallback на XML при ошибке; `load_plist_safe` умеет восстанавливать повреждённые XML/bplist файлы, вычищая недопустимые управляющие байты.
- **Санитизация имён файлов** (`sanitize_filename` в `main.py`) — при работе с `.appex` и другими именами из архива предотвращается выход за пределы директории через `../` или абсолютные пути.
- **Ограничения размера при глубоком патче** — файлы крупнее 200 МБ (бинарники) или 50 МБ (текстовые) пропускаются при глубокой замене Bundle ID/версии, чтобы не читать в память слишком большие файлы.
- **Бэкапы и undo в Hex-патчере** — перед прямой правкой байтов менеджер бэкапов (`hex_patcher/managers/`) сохраняет предыдущее состояние файла, что позволяет откатить точечные изменения без пересборки IPA с нуля.

## 🔬 Работа с Mach-O

Весь разбор и модификация бинарников реализована вручную через `struct`, без сторонних библиотек типа `lief` или `macholib`:

- **`is_macho_binary`** — определяет тип файла по magic-числу (`MH_MAGIC_64`, `MH_CIGAM_64`, `MH_MAGIC_32`, `MH_CIGAM_32`, `FAT_MAGIC`, `FAT_CIGAM`), проверяя оба порядка байт.
- **`inject_lc_load_dylib`** — добавляет новую load-команду `LC_LOAD_DYLIB`, корректно работает как с обычными, так и с FAT (universal) бинарниками; перед вставкой ищет свободное место до начала первой секции и отказывается работать, если места недостаточно.
- **`inject_rpath`** / **`has_rpath`** — добавляет и проверяет наличие `LC_RPATH`.
- **`inject_code_signature`** — низкоуровневая запись `LC_CODE_SIGNATURE` (offset/size super-блоба подписи) — служебная функция для работы с сигнатурами.
- **`is_ipa_encrypted`** — читает `LC_ENCRYPTION_INFO` / `LC_ENCRYPTION_INFO_64` и поле `cryptid`, чтобы определить, расшифрован ли App Store бинарник, прежде чем разрешать инъекцию.
- **`thin_binary_to_arm64`** — вырезает arm64/arm64e-срез из FAT-бинарника и перезаписывает файл только им.
- **`verify_binary_architecture`** (в `tweak_injector.py`) — отклоняет 32-битные (ARMv7/v7s) бинарники и FAT-файлы без современного 64-битного среза ещё до начала инъекции.

Все операции поддерживают как тонкие (thin), так и универсальные (FAT/ARM64) бинарники, и включают проверки границ (`max_offset`), защищающие от чтения/записи за пределами буфера на повреждённых файлах.

## 🌐 Web Transfer — передача файлов по Wi-Fi

`web_transfer.py` — независимый вспомогательный модуль (запускается отдельно, `python3 web_transfer.py`) для загрузки `.ipa`/`.zip`/`.deb`/`.dylib` на устройство без кабеля, если файлы неудобно передавать иначе.

**Безопасность:**

- Доступ к загрузке защищён 6-значным ПИН-кодом (генерируется случайно при каждом запуске сервера, сравнение — через `secrets.compare_digest`).
- Rate-limit: не более 5 запросов в минуту с одного IP.
- Автобан IP на 10 минут после 5 неудачных попыток ввода ПИН-кода; чёрный список сохраняется в `blacklist.json` и переживает перезапуск.
- Ограничение одновременных соединений (`MAX_CONNECTIONS`).
- Проверка расширений (`.ipa`, `.zip`, `.deb`, `.dylib`) и лимит размера файла (500 МБ по умолчанию).
- Санитизация имён файлов и защита от directory traversal (`is_safe_path`).
- HTTP-заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, CSP, `Referrer-Policy`.
- Отдельные логи: `web_transfer.log` (общий) и `audit.log` (события безопасности, с маскированием IP).

**Использование:** запусти модуль, выбери “Запустить защищённый сервер” в меню, открой `http://<IP>:8080` в браузере на компьютере, введи показанный на экране ПИН и перетащи файл — он появится в `~/Documents/IPA_Patcher_Files/`.

## ❓ FAQ

**Нужен ли джейлбрейк?**
Нет. Установка через AltStore или SideStore работает на стоковой iOS.

**Какая версия Pythonista нужна?**
Pythonista 3.4 и новее.

**Можно ли откатить изменения?**
Скрипт никогда не изменяет исходный `.ipa` — результат всегда сохраняется в новый файл с суффиксами (`_tweaked`, `_icon`, `_patched`) в зависимости от применённых изменений. Точечные правки через Hex-патчер дополнительно можно откатить через встроенный менеджер бэкапов/undo до финальной сборки.

**Почему инъекция твика не удалась?**
Чаще всего — нехватка свободного места в заголовке Mach-O перед первой секцией, неподдерживаемая архитектура бинарника (32-бит), либо исходный `.ipa` зашифрован (App Store бинарник без предварительной расшифровки).

**Какой метод замены иконки выбрать?**
Для большинства случаев подходит гибридный метод (`1`) — он не трогает `Assets.car` целиком и поэтому не рискует крашем приложения на iOS 15+, но при этом надёжно переопределяет отображаемую иконку. Полное удаление `Assets.car` (`5`) стоит использовать только если гибридный метод не сработал и вы понимаете риски.

**Для чего нужен Hex патчер, если есть остальные пункты меню?**
Остальные пункты меню решают типовые задачи (замена ID, версии, иконки, инъекция твика) через готовые сценарии. Hex-патчер нужен, когда требуется точечная правка произвольных байтов или строк в конкретном файле — например, патч специфичной проверки в стороннем бинарнике, — для которой нет отдельного пункта меню.

**Обязателен ли Pillow?**
Нет. Без Pillow иконки просто копируются как есть без ресайза под нужный размер — это может выглядеть менее аккуратно, но функционально работает.

**Поддерживаются ли `.deb`-пакеты с вложенными архивами?**
Да, скрипт рекурсивно находит и распаковывает `data.tar.{gz,xz,lzma}` внутри `.deb`, а также резолвит зависимости из `DEBIAN/control`.

**Что если новый Bundle ID или версия длиннее старых?**
Глубокая замена в бинарниках для такого файла автоматически пропускается (чтобы не сломать файл смещением байтов) — правка через `Info.plist` при этом всё равно применяется.

**Обязателен ли `libsubstrate.dylib`?**
Нет. Он нужен только при инъекции твиков в режиме субстрата “авто”. В режиме “свой файл” можно указать любой `.dylib`, а в режиме “без субстрата” твики инъектируются напрямую без зависимости от Substrate/libhooker.

## 📦 Требования

- Python 3.6+
- Стандартная библиотека Python (`zipfile`, `plistlib`, `struct`, `shutil`, `tempfile`, `ctypes`, `http.server`, `mmap`)
- **Pillow** (опционально) — для качественного ресайза и оптимизации иконок; без неё используется прямое копирование
- Для iOS/iPadOS: [Pythonista 3](https://apps.apple.com/app/pythonista-3/id1085978097) (App Store, платное приложение)
- Для распаковки `.deb`/`.tar.*`: системная `libarchive.2.dylib` (присутствует в iOS/Pythonista по умолчанию)
- Для инъекции твиков: расшифрованный IPA + `libsubstrate.dylib` (опционально, если выбран ручной/авто-режим субстрата)
