## 🧩 Что это такое

**IPA Patcher Lite** — консольный инструмент для модификации `.ipa`-пакетов: смены идентификаторов и метаданных приложения, настройки entitlements, гибридной замены иконки (с маскировкой `Assets.car` вместо его удаления), настройки файлового шеринга, инъекции твиков (`.dylib`, MobileSubstrate-пакеты, `.deb`, фреймворки), расширенных патчей (понижение версии iOS, снятие ограничений по устройствам, удаление плагинов), встроенного Hex-редактора для точечного бинарного патчинга, интерактивного файлового менеджера для просмотра и редактирования файлов внутри `.app`, а также подготовки пакета к установке через **SideStore** или **AltStore** — без джейлбрейка, компилятора и сторонних библиотек.

Парсер Mach-O, инъектор load-команд и распаковщик архивов написаны на чистом Python и работают на **Pythonista 3** и **a-Shell mini** на iPhone/iPad, а также нативно на macOS, Linux и Windows. Скрипт сам определяет окружение через `try/except import` и `sys.platform` и адаптирует под него распаковку архивов, файловые диалоги и доступные системные функции (например, Share Sheet работает только в Pythonista на iOS). Все операции с файловой системой и архивами защищены от directory traversal и содержат ограничения на размер/структуру данных, чтобы не падать и не портить бинарники на повреждённых или враждебных входных файлах.

## ✨ Возможности

| Категория | Описание |
|-----------|----------|
| 📦 **Распаковка / упаковка IPA** | Извлекает и собирает `.ipa` (ZIP) с сохранением Unix-прав доступа; временная папка создаётся в `~/Documents/ipa_patcher/tmp/` и автоматически очищается по завершении работы |
| ✏️ **Редактирование Info.plist** | Имя (`CFBundleDisplayName` / `CFBundleName`), версия (`CFBundleShortVersionString`), номер сборки (`CFBundleVersion`); безопасное чтение/запись plist с fallback-восстановлением повреждённых файлов |
| 🔑 **Смена Bundle ID** | Каскадно обновляет идентификатор в основном `Info.plist`, во всех `PlugIns/*.appex`, в `Watch/*.app` и любых вложенных `.appex` по дереву `.app` |
| 🧬 **Глубокая замена ID и версии** | Единая функция побайтового патча (`deep_patch_string_in_bundle`) для Bundle ID и версии внутри всех Mach-O бинарников и текстовых файлов пакета до 200 МБ (кроме `Info.plist`, `entitlements.plist`, `embedded.mobileprovision`); в логе выводится точное число вхождений |
| 🔐 **Настройка Entitlements** | Генерация `entitlements.plist` с автоопределением Team ID из `embedded.mobileprovision`, поддержка бесплатных и платных Apple ID (JIT/get-task-allow, Extended VM, Push, Associated Domains, iCloud) |
| 📁 **Файловый шеринг: 3 режима** | Старый (только `UIFileSharingEnabled`), современный (только `LSSupportsOpeningDocumentsInPlace`) или гибридный (оба ключа); во всех режимах дополнительно включается `UISupportsDocumentBrowser` для системного браузера файлов |
| 🖼️ **Гибридная замена иконки** | 5 методов на выбор: гибридный (маскировка `Assets.car` + loose-иконки), только маскировка BOM-индекса, только loose-иконки, стандартная файловая замена, полное удаление `Assets.car`. `Assets.car` по умолчанию остаётся нетронутым |
| 🎨 **Оптимизация иконок через Pillow** | Автоматический ресайз под нужный размер (`@2x`/`@3x`/`~ipad`), квантование мелких значков, при отсутствии Pillow — безопасный fallback на прямое копирование |
| 🔢 **Автоинкремент CFBundleVersion** | При замене иконки автоматически увеличивает номер сборки, чтобы iOS сбросила кэш иконок в SpringBoard |
| 💉 **Инъекция твиков** | `.dylib`, `.zip`, `.deb` (с рекурсивной распаковкой `data.tar.*`), `.tar`, `.lzma`, `.xz`, `.gz`, `.tgz` — фреймворки, бандлы и динамические библиотеки автоматически находятся и копируются в `Frameworks/` |
| 🌍 **Кроссплатформенная распаковка архивов** | На iOS использует системную `libarchive.2.dylib` через ctypes; на macOS/Linux — системную утилиту `ar` для `.deb` и модуль `tarfile` для остальных форматов; на Windows — чистый Python-парсер `ar`-контейнера и `tarfile`. Везде действует защита от path traversal |
| 🧬 **Substrate-инъекция** | Три режима: автоматическая (встроенный `libsubstrate.dylib` рядом со скриптом), ручная (свой `.dylib`) или полное отключение |
| 🛡️ **Проверка dylib перед инъекцией** | Валидация заголовков Mach-O (`verify_dylib_headers`), отклонение 32-битных файлов, сканирование на подозрительные системные вызовы (`system`, `popen`, `exec*`, IOKit-функции) перед копированием в бандл |
| 🛣️ **@rpath / @executable_path** | Переключаемый режим путей загрузки динамических библиотек |
| 🔍 **Проверка шифрования** | Определяет `LC_ENCRYPTION_INFO` / `LC_ENCRYPTION_INFO_64` (`cryptid`) перед инъекцией, чтобы не сломать зашифрованный бинарник |
| 🩻 **Проверка архитектуры и thinning** | Валидирует, что бинарник ARM64/ARM64e (отклоняет чистый ARMv7/v7s), и автоматически “утоньшает” FAT-бинарник до arm64-среза перед инъекцией |
| 🧵 **Патч строк в бинарниках** | Побайтовая замена путей загрузки во всех Mach-O файлах внутри `Frameworks/` с сохранением длины и `\x00`-паддинга (через `mmap`) |
| 🛠️ **Расширенные патчи** | Понижение `MinimumOSVersion`, удаление `UISupportedDevices`, удаление `PlugIns` (расширений), удаление Apple Watch компонентов, удаление `CFBundleURLTypes`, фикс белой иконки |
| 📝 **Расширенное редактирование JSON** | Полный `Info.plist` экспортируется во временный JSON-файл, который можно отредактировать в любом текстовом редакторе; при изменении Bundle ID или версии сразу предлагается выбрать безопасный или глубокий режим замены; временный файл удаляется автоматически |
| 🔧 **Hex патчер** | Встроенный интерактивный Hex-редактор (пункт 15, `hex_patcher/`) для поиска и замены HEX/строк в любом файле `.app`; поддержка масок, undo и бэкапов; изменения сохраняются в файлах и попадают в финальный IPA |
| 📁 **Файловый менеджер** | Интерактивный файловый менеджер (пункт 8) для навигации по папкам `.app`, просмотра и редактирования файлов, работы с Mach-O бинарниками и plist/JSON файлами с созданием резервных копий |
| ✅ **Строгая валидация ввода y/n** | `ask_yes_no` принимает только `y`/`yes`/`д`/`да` или `n`/`no`/`н`/`нет` и переспрашивает при любом другом вводе — исключает случайный пропуск важного шага |
| 🧹 **Удаление подписи и мусора** | Чистит `_CodeSignature/`, `SC_Info/`, `embedded.mobileprovision`, `CodeResources`, папки `Library`/`Applications`/`DEBIAN`, а также артефакт чужой подписи `SignedByEsign`, если он остался от исходного IPA |
| 🗑️ **Автоочистка после запуска** | По завершении (успешном или прерванном) скрипт удаляет временную папку `~/Documents/ipa_patcher/tmp/` и `undo_log.json` Hex-патчера |
| 📲 **Прямая отправка в SideStore / AltStore** | На iOS в Pythonista открывает системный Share Sheet; на остальных платформах сообщает, что файл сохранён на диск |
| 🌐 **Web Transfer** | Отдельный модуль — локальный HTTP-сервер с ПИН-кодом, rate-limit’ом и авто-баном для передачи `.ipa`/`.zip`/`.deb`/`.dylib` на устройство по Wi-Fi без кабеля и iTunes |
| 📱 **Умный выбор файлов** | В Pythonista — системные диалоги `dialogs.pick_document`; на остальных платформах и в a-Shell mini — список файлов, найденных в `~/Documents/ipa_patcher/tmp/`, с возможностью выбрать по номеру или ввести путь вручную |

## 🚀 Установка

### 📱 iPhone / iPad — Pythonista 3

1. Установи [Pythonista 3](https://apps.apple.com/app/pythonista-3/id1085978097) из App Store.
2. Скопируй все файлы проекта (включая папки `icon_tools/`, `file_explorer/` и `hex_patcher/`) в **Pythonista → Documents** (`libsubstrate.dylib` — только если планируешь инъекцию твиков в режиме “авто”).
3. Готово — остальное работает на стандартной библиотеке.

### 📱 iPhone / iPad — a-Shell mini

1. Установи [a-Shell mini](https://apps.apple.com/app/a-shell-mini/id1543537943) из App Store.
2. Открой a-Shell mini и перейди в папку Documents: `cd ~/Documents`.
3. Скопируй все файлы проекта в эту папку (например, через iCloud Drive, AirDrop или файловый менеджер).
4. Запусти скрипт: `python3 main.py`.

### 🖥️ macOS / Linux / Windows — Python

```bash
git clone https://github.com/andreygirin144-netizen/ipa-patcher.git
cd ipa-patcher
pip install Pillow   # опционально, для качественной генерации иконок
python3 main.py
```

> Функция Share Sheet (прямая установка через SideStore/AltStore) доступна только в Pythonista на iOS/iPadOS. На остальных платформах скрипт просто сообщает, что готовый файл сохранён на диск.

## 🕹 Использование

### Pythonista 3 (iOS/iPadOS)

1. Открой `main.py` в Pythonista и нажми **▶ Run**.
2. Выбери `.ipa` через системный файловый пикер.
3. Пройдись по пунктам меню (имя, версия, иконка, файловый шеринг, твики, entitlements, расширенные патчи, Hex-патчер, файловый менеджер и т.д.).

## 📁 Файловый шеринг: 3 режима

Пункт `5` открывает выбор из трёх стратегий:

| № | Режим | Что включается |
|---|-------|----------------|
| 1 | **Старый** | Только `UIFileSharingEnabled` — классический доступ к папке `Documents` приложения через iTunes/Finder |
| 2 | **Современный (iOS 14+)** | Только `LSSupportsOpeningDocumentsInPlace` — открытие документов на месте через Files app |
| 3 | **Гибридный (рекомендуется)** | Оба ключа одновременно — максимальная совместимость со старыми и новыми версиями iOS |

Независимо от выбранного режима, всегда дополнительно включается `UISupportsDocumentBrowser`, который делает папку приложения видимой в системном браузере файлов (Files app) — без этого ключа приложение может не отображаться в списке “На iPhone” даже с включённым файловым шерингом.

При выборе конкретного режима соответствующий “лишний” ключ из другого режима удаляется из `Info.plist`, если он там был — так что переключение между режимами при повторном патче происходит чисто, без накопления неиспользуемых ключей.

## 🖼️ Замена иконки: 5 методов

Пункт `6` открывает выбор из пяти стратегий (`icon_tools/icon_manager.py` / `icon_tools/icon_generator.py` / `icon_tools/boms_editor.py`). Поддерживаются только PNG-файлы в качестве источника.

| № | Метод | Что происходит |
|---|-------|----------------|
| 1 | **Гибридный (рекомендуется)** | Последовательно: обрабатывает все бандлы приложения (главный + `.appex`/`Watch`) → стандартная файловая замена существующих иконок → маскировка токенов в `Assets.car` → legacy loose-метод с очисткой современных ключей `CFBundleIcons`. `Assets.car` остаётся на месте — приложение не падает из-за отсутствующих ресурсов |
| 2 | **Только маскировка Assets.car** | Патчит только бинарный BOM-индекс (`patch_boms_icon`), без замены файлов иконок — самый безопасный, но менее надёжный способ заставить iOS не использовать кэш |
| 3 | **Только loose-иконки** | Генерирует полный набор PNG нужных размеров (`generate_loose_icons`) и переписывает `CFBundleIcons*`/`CFBundleIconFiles` в `Info.plist`, чтобы iOS взяла иконки из файлов, а не из `Assets.car` |
| 4 | **Только стандартная замена** | Ищет существующие файлы иконок по именам из `Info.plist` и подменяет их напрямую (`replace_icon_standard`) |
| 5 | **Удалить Assets.car** | ⚠️ Требует отдельного подтверждения — на iOS/iPadOS 15+ приложение может крашиться при запуске без `Assets.car` |

**Как работает анализ (`icon_tools/icon_analyzer.py`):**

- Извлекает имена иконок из `CFBundleIcons`, `CFBundleIcons~ipad`, легаси `CFBundleIconFiles` и `CFBundleIconName`.
- Строит полный список возможных вариантов имён (`@2x`/`@3x`, `~iphone`/`~ipad`, стандартные `AppIcon*`/`Icon*`, `iTunesArtwork`) и сканирует директорию `.app` на совпадения regex-паттерном.
- При наличии **Pillow** — ресайзит источник под нужный размер (LANCZOS/ANTIALIAS в зависимости от версии Pillow) и квантует мелкие иконки (≤40×40) до 128 цветов для меньшего размера файла; без Pillow — прямое копирование оригинала как fallback (без ресайза, но без ошибки).
- После успешной замены **автоматически увеличивает `CFBundleVersion`** на 1 (`increment_bundle_version`), чтобы SpringBoard сбросил кэш иконок.

**Маскировка Assets.car (`icon_tools/boms_editor.py`):**

Файл `Assets.car` — это `BOMStore`-контейнер (Bill of Materials), внутри которого есть индексные ключи вида `CFBundleIconFiles`, `AppIcon-` и т.д. Модуль ищет эти ключи побайтово и заменяет их на строки **той же длины** (`XFBundleIconFiles`, `XppIcon-` и т.п.), не трогая остальную структуру файла. Это “отключает” привязку системы к закэшированным иконкам внутри `Assets.car`, не удаляя сам файл и не ломая остальные ресурсы (шрифты, изображения интерфейса и т.д.), которые там тоже могут храниться.

## 💉 Инъекция твиков подробно

### Поддерживаемые форматы

| Формат | Обработка |
|--------|-----------|
| `.dylib` | Проверяются заголовки Mach-O (`verify_dylib_headers`): magic-число, разрядность, наличие ARM64/ARM64e среза — отклоняются 32-битные файлы; при неудачной проверке запрашивается подтверждение на свой риск |
| `.zip` | Распаковывается стандартным `zipfile` с фильтрацией путей на traversal; если внутри одна папка — она становится корнем поиска |
| `.deb` | На iOS — через системную `libarchive.2.dylib` (ctypes); на macOS/Linux — через системную утилиту `ar`; на Windows — чистым Python-парсером `ar`-контейнера. Затем рекурсивно ищется и распаковывается вложенный `data.tar.{gz,xz,lzma}` |
| `.tar`, `.lzma`, `.xz`, `.gz`, `.tgz` | На iOS — через `libarchive.2.dylib`; на остальных платформах — через модуль `tarfile` с проверкой путей на traversal и корректным разрешением символических ссылок |

### Что и как ищется внутри архива

1. **`Library/MobileSubstrate/DynamicLibraries/`** — основной путь поиска `.dylib`; корректно разрешает симлинки (`os.readlink`), если найдена ссылка вместо файла.
2. Если такой папки нет — поиск `.dylib` идёт рекурсивно по всему архиву.
3. **`Library/Frameworks/*.framework`** копируются целиком (с fallback-поиском по всему дереву, если структуры `Library/Frameworks` нет).
4. Для `.deb` дополнительно разбирается `DEBIAN/control` — из поля `Depends:` резолвятся зависимости (сначала как `.dylib`, потом как `.framework`) и подтягиваются, если найдены в архиве.
5. Любые `*.bundle`-директории копируются в `Frameworks/` как есть (ресурсы твика).
6. Папки `Applications/` и `DEBIAN/` удаляются как непригодные для пользовательского приложения.

### Пайплайн инъекции

1. Проверка, что главный исполняемый файл (`CFBundleExecutable`) — валидный Mach-O с поддерживаемой архитектурой (ARM64/ARM64e; чистый ARMv7/v7s отклоняется).
2. Если бинарник FAT — он “утоньшается” до arm64-среза (`thin_binary_to_arm64`).
3. Создаётся `Frameworks/`, туда копируются найденные `.dylib`/`.framework`/`.bundle`; для каждого зависимого файла проверяются подозрительные системные вызовы и патчатся пути к CydiaSubstrate на `sb.dylib`.
4. Оценивается количество модулей (`count_modules_in_tweak`) и заранее проверяется, хватит ли места в заголовке Mach-O под нужные load-команды.
5. В главный бинарник добавляются `LC_RPATH` для `@executable_path/` и `@executable_path/Frameworks`.
6. Если субстрат включён — `libsubstrate.dylib` (или выбранный вручную файл) копируется как `sb.dylib` в корень `.app`, в бинарник добавляется `LC_LOAD_DYLIB`.
7. Во всех скопированных Mach-O файлах побайтово патчатся старые пути (`/Library/MobileSubstrate/DynamicLibraries/`, пути к фреймворкам) на новые (`@executable_path/...` или `@rpath/...`, в зависимости от выбранного режима).
8. Для каждого `.dylib` и `.framework` в главный бинарник добавляется собственный `LC_LOAD_DYLIB`.
9. Если ни одна инъекция не удалась (не хватило места в заголовке) — операция считается неуспешной и сообщается пользователю.

## 🧬 Глубокая замена Bundle ID / версии

Помимо правки `Info.plist`, при смене Bundle ID или версии (пункты `2` и `4`, а также при правке через JSON-редактор) можно выбрать **глубокую замену** — она реализована единой функцией `deep_patch_string_in_bundle`, общей для обоих случаев:

- Скрипт проходит по всем файлам `.app`, пропуская медиа/шрифты/скомпилированные сториборды/`.car`, а также `Info.plist`, `entitlements.plist` и `embedded.mobileprovision`.
- Mach-O бинарники патчатся через `patch_strings.py` (безопасная побайтовая замена с `\x00`-паддингом через `mmap`, без сдвига файла); в лог выводится **точное число замен** в каждом файле.
- Обычные файлы (json, конфиги, файлы Unity вроде `global-metadata.dat`) патчатся прямой заменой байтовой строки — лимит размера файла для проверки поднят до **200 МБ**.
- **Ограничение:** новое значение не должно быть длиннее старого в байтах UTF-8 — иначе глубокая замена для конкретного файла пропускается (замена только через `Info.plist` всё равно применяется).
- Bundle ID дополнительно каскадно обновляется в `Info.plist` всех `PlugIns/*.appex` и `Watch/*.app`.

## 🔧 Hex патчер

Пункт меню `15` открывает встроенный интерактивный Hex-редактор (`hex_patcher/`). Он позволяет выполнять низкоуровневый поиск и замену байтов/строк прямо внутри файлов уже распакованного `.app` — без необходимости пересобирать IPA и заново открывать его в стороннем Hex-редакторе.

После выбора `.app` скрипт предоставляет доступ ко всем файлам внутри него (основной бинарник, `Assets.car` и любые другие). Внутри Hex-редактора доступны следующие функции:

- **Просмотр дампа файла** с настраиваемым интервалом, количеством строк и разбивкой; крупные файлы (>10 МБ) автоматически обрезаются до первых 10 МБ для быстрой навигации.
- **Поиск** HEX-последовательностей, точных строк и строк без учёта регистра; найденные смещения сохраняются и могут быть использованы для замены.
- **Поиск и замена** HEX или текста — поддерживается пакетная замена всех совпадений или только выбранных пользователем номеров.
- **Редактирование по смещению** — замена байтов начиная с конкретного адреса (hex или decimal) с предварительным просмотром текущих байтов и их ASCII-представления.
- **Список найденных смещений** — все совпадения выводятся с номерами, что позволяет быстро переключаться между ними и применять замены.

Модуль организован как отдельный подпакет `hex_patcher/`:

- `core/` — движок патчинга, исключения, типы данных.
- `analyzers/` — анализ структуры Mach-O и поисковые алгоритмы.
- `managers/` — управление бэкапами файлов и историей изменений (`undo_log.json`).
- `utils/` — вспомогательные функции для дампа и конвертации hex/ASCII.
- `cli/` — интерактивный консольный интерфейс редактора.
- `json_patcher.py` — загрузка и сохранение наборов патчей в формате JSON (для повторного применения одинаковых правок к разным сборкам).

Все изменения, внесённые через Hex-редактор, применяются прямо в файлах внутри временной директории сборки. При использовании Hex-патчера в текущей сессии флаг `hex_patcher_used` устанавливается независимо от других изменений, и итоговый IPA автоматически получает суффикс `_patched` даже если больше ничего не менялось. По завершении работы скрипта временный `undo_log.json` автоматически удаляется вместе с остальным содержимым `tmp/`.

## 📁 Файловый менеджер

Пункт меню `8` открывает интерактивный файловый менеджер (`file_explorer/`), который позволяет:

- **Навигация по папкам** внутри `.app` с отображением количества элементов в директориях.
- **Поиск файлов** по шаблону (например, `*.plist`, `*.dylib`, `Info`) по всему `.app`.
- **Определение типов файлов**: папки (`[DIR]`), Mach-O бинарники (`[Mach-O]`), текстовые файлы (`[Text]`), обычные файлы.
- **Инструменты для Mach-O бинарников**:
  - Просмотр списка зависимостей (`LC_LOAD_DYLIB`).
  - Изменение путей зависимостей с префиксами (`@executable_path/`, `@loader_path/`, `@rpath/`).
  - Добавление новых зависимостей.
  - Восстановление из резервной копии.
  - Информация о файле (размер, архитектуры, количество зависимостей).
- **Редактирование файлов**:
  - JSON — автоматическое определение кодировки, проверка валидности, форматирование.
  - Plist — интерактивный редактор ключ-значение с поддержкой типов (строки, числа, булевы, массивы).
  - Текстовые файлы — редактирование через временный файл с выбором редактора.
  - Бинарные файлы — открытие в Hex-редакторе.
- **Создание резервных копий** файлов перед редактированием с автоматической очисткой старых копий.
- **Просмотр содержимого** текстовых и бинарных файлов с автоматическим определением кодировки и HEX-дампом для бинарных данных.

Модуль `file_explorer/` организован следующим образом:

- `browser.py` — основной цикл файлового менеджера, навигация, поиск.
- `file_actions.py` — действия с файлами: просмотр, редактирование JSON/plist/text, Hex-редактор.
- `macho_tools.py` — инструменты для Mach-O бинарников: зависимости, инъекция, восстановление.
- `plist_tools.py` — интерактивный редактор plist (ключ-значение).
- `text_viewer.py` — просмотр текстовых и бинарных файлов, HEX-дамп.
- `backups.py` — создание/восстановление резервных копий файлов.
- `types.py` — Dataclass-типы: `BackupInfo`, `FileInfo`, `ChangeSummary`.
- `utils.py` — утилиты: `is_safe_path`, `format_file_size`, `count_items_in_dir`, `is_text_extension`.

Все изменения, внесённые через файловый менеджер, попадают в общую сводку изменений при сборке IPA.

## 🛡️ Безопасность и защита

В основной пайплайн встроен ряд защитных механизмов, снижающих риск повреждения бинарников и файловой системы на нестандартных или вредоносных входных данных:

- **Path traversal / Zip Slip защита** — при распаковке `.ipa`, `.zip`-твиков и любых архивов через `libarchive`/`ar`/`tarfile` (`tweak_injector.py`) все пути внутри архива проверяются на выход за пределы целевой директории (`os.path.realpath(...).startswith(...)`) перед извлечением — независимо от платформы и используемого метода распаковки.
- **Строгий парсинг Mach-O** — все функции разбора load-команд (`macho.py`) ограничивают `ncmds` (не более 1000), размер отдельной команды (`cmdsize` не более 4096 байт) и число архитектур в FAT-бинарнике (1–20), а также постоянно сверяют смещения с фактическим размером файла перед чтением/записью — это предотвращает падения и переполнения на повреждённых бинарниках.
- **Сканирование dylib на подозрительные вызовы** (`substrate.py`) — перед добавлением зависимости твика в бандл проверяется наличие символов вроде `system`, `popen`, `exec*`, `fork`, `ptrace`, IOKit-функций (`IOServiceMatching`, `IOConnectCallMethod` и т.д.); при обнаружении выводится предупреждение, но решение остаётся за пользователем.
- **Проверка заголовков dylib перед инъекцией** (`verify_dylib_headers` в `tweak_injector.py`) — отдельно от общей проверки архитектуры, отклоняет 32-битные dylib и файлы без валидного ARM64/ARM64e среза.
- **Безопасная запись plist** (`plist_editor.py`) — `save_plist`/`save_plist_safe` пишут в бинарном формате с автоматическим fallback на XML при ошибке; `load_plist_safe` умеет восстанавливать повреждённые XML/bplist файлы, вычищая недопустимые управляющие байты.
- **Санитизация имён файлов** (`sanitize_filename` в `main.py`) — при работе с `.appex` и другими именами из архива предотвращается выход за пределы директории через `../` или абсолютные пути.
- **Строгая валидация y/n-ввода** (`ask_yes_no` в `utils.py`) — принимает только явные `y`/`yes`/`д`/`да` или `n`/`no`/`н`/`нет`, любой другой символ (включая пробел, цифры, случайные буквы) не интерпретируется как ответ по умолчанию, а вызывает повторный запрос.
- **Ограничения размера при глубоком патче** — единый лимит 200 МБ на файл при глубокой замене Bundle ID/версии (включая крупные файлы вроде `global-metadata.dat` в Unity-приложениях), чтобы не читать в память слишком большие файлы без ограничений.
- **Бэкапы и undo в Hex-патчере** — перед прямой правкой байтов менеджер бэкапов (`hex_patcher/managers/`) сохраняет предыдущее состояние файла и ведёт журнал в `undo_log.json`, что позволяет откатить точечные изменения без пересборки IPA с нуля.
- **Автоочистка временных артефактов** — папка `tmp/` и `undo_log.json` удаляются в блоке `finally` при любом сценарии завершения работы (успех, ошибка, `Ctrl+C`), не оставляя следов патчинга на диске.

## 🔬 Работа с Mach-O

Весь разбор и модификация бинарников реализована вручную через `struct`, без сторонних библиотек типа `lief` или `macholib`:

- **`is_macho_binary`** — определяет тип файла по magic-числу (`MH_MAGIC_64`, `MH_CIGAM_64`, `MH_MAGIC_32`, `MH_CIGAM_32`, `FAT_MAGIC`, `FAT_CIGAM`), проверяя оба порядка байт.
- **`inject_lc_load_dylib`** — добавляет новую load-команду `LC_LOAD_DYLIB`, корректно работает как с обычными, так и с FAT (universal) бинарниками; перед вставкой ищет свободное место до начала первой секции и отказывается работать, если места недостаточно.
- **`inject_rpath`** / **`has_rpath`** — добавляет и проверяет наличие `LC_RPATH`.
- **`inject_code_signature`** — низкоуровневая запись `LC_CODE_SIGNATURE` (offset/size super-блоба подписи) — служебная функция для работы с сигнатурами.
- **`is_ipa_encrypted`** — читает `LC_ENCRYPTION_INFO` / `LC_ENCRYPTION_INFO_64` и поле `cryptid`, чтобы определить, расшифрован ли App Store бинарник, прежде чем разрешать инъекцию.
- **`thin_binary_to_arm64`** — вырезает arm64/arm64e-срез из FAT-бинарника и перезаписывает файл только им.
- **`verify_binary_architecture`** (в `tweak_injector.py`) — отклоняет 32-битные (ARMv7/v7s) бинарники и FAT-файлы без современного 64-битного среза ещё до начала инъекции.

Все операции поддерживают как тонкие (thin), так и универсальные (FAT/ARM64) бинарники, и включают проверки границ, защищающие от чтения/записи за пределами буфера на повреждённых файлах.

## 🌐 Web Transfer — передача файлов по Wi-Fi

`web_transfer.py` — независимый вспомогательный модуль (запускается отдельно, `python3 web_transfer.py`) для загрузки `.ipa`/`.zip`/`.deb`/`.dylib` на устройство без кабеля, если файлы неудобно передавать иначе.

**Безопасность:**

- Доступ к загрузке защищён 6-значным ПИН-кодом (генерируется случайно при каждом запуске сервера, сравнение — через `secrets.compare_digest`).
- Rate-limit: не более 5 запросов в минуту с одного IP.
- Автобан IP на 10 минут после 5 неудачных попыток ввода ПИН-кода; чёрный список сохраняется в `blacklist.json` и переживает перезапуск.
- Ограничение одновременных соединений (`MAX_CONNECTIONS`).
- Проверка расширений (`.ipa`, `.zip`, `.deb`, `.dylib`) и лимит размера файла (500 МБ по умолчанию).
- Санитизация имён файлов и защита от directory traversal (`is_safe_path`).
- HTTP-заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, CSP, `Referrer-Policy`.
- Отдельные логи: `web_transfer.log` (общий) и `audit.log` (события безопасности, с маскированием IP).

**Использование:** запусти модуль, выбери “Запустить защищённый сервер” в меню, открой `http://<IP>:8080` в браузере на компьютере, введи показанный на экране ПИН и перетащи файл — он появится в `~/Documents/IPA_Patcher_Files/`.

## ❓ FAQ

**Нужен ли джейлбрейк?**
Нет. Установка через AltStore или SideStore работает на стоковой iOS.

**Какие платформы поддерживаются?**
Pythonista 3 и a-Shell mini на iOS/iPadOS, а также нативный Python на macOS, Linux и Windows. Функциональность патчинга одинакова везде, отличаются только способ выбора файлов и наличие Share Sheet.

**Можно ли откатить изменения?**
Скрипт никогда не изменяет исходный `.ipa` — результат всегда сохраняется в новый файл с суффиксами (`_tweaked`, `_icon`, `_patched`) в зависимости от применённых изменений. Точечные правки через Hex-патчер дополнительно можно откатить через встроенный менеджер бэкапов/undo до финальной сборки.

**Почему инъекция твика не удалась?**
Чаще всего — нехватка свободного места в заголовке Mach-O перед первой секцией, неподдерживаемая архитектура бинарника (32-бит), либо исходный `.ipa` зашифрован (App Store бинарник без предварительной расшифровки).

**Какой режим файлового шеринга выбрать?**
Для большинства случаев подходит гибридный (`3`) — он обеспечивает совместимость и со старыми, и с новыми версиями iOS. Старый режим стоит выбирать только для целевой iOS ниже 14, современный — если приложение точно не будет запускаться на устаревших версиях.

**Какой метод замены иконки выбрать?**
Для большинства случаев подходит гибридный метод (`1`) — он не трогает `Assets.car` целиком и поэтому не рискует крашем приложения на iOS 15+, но при этом надёжно переопределяет отображаемую иконку. Полное удаление `Assets.car` (`5`) стоит использовать только если гибридный метод не сработал и вы понимаете риски.

**Для чего нужен Hex патчер, если есть остальные пункты меню?**
Остальные пункты меню решают типовые задачи (замена ID, версии, иконки, инъекция твика) через готовые сценарии. Hex-патчер нужен, когда требуется точечная правка произвольных байтов или строк в конкретном файле — например, патч специфичной проверки в стороннем бинарнике

**Обязателен ли Pillow?**
Нет. Без Pillow иконки просто копируются как есть без ресайза под нужный размер — это может выглядеть менее аккуратно, но функционально работает без ошибок.

**Поддерживаются ли `.deb`-пакеты с вложенными архивами?**
Да, скрипт рекурсивно находит и распаковывает `data.tar.{gz,xz,lzma}` внутри `.deb`, а также резолвит зависимости из `DEBIAN/control` — на любой из поддерживаемых платформ.

**Что если новый Bundle ID или версия длиннее старых?**
Глубокая замена в бинарниках для такого файла автоматически пропускается (чтобы не сломать файл смещением байтов) — правка через `Info.plist` при этом всё равно применяется.

**Обязателен ли `libsubstrate.dylib`?**
Нет. Он нужен только при инъекции твиков в режиме субстрата “авто”. В режиме “свой файл” можно указать любой `.dylib`, а в режиме “без субстрата” твики инъектируются напрямую без зависимости от Substrate/libhooker.
